# Quantum application-hosted custody tests

`TOSCustodyHostedTests` requires an application host with Keychain entitlements.
Run it through the repository Makefile on a dedicated simulator. An unhosted
package process returns `errSecMissingEntitlement`; that is not evidence of the
required missing-record refusal.

Set `TEST_DESTINATION` to the dedicated simulator destination before running:

```sh
make test_project_scheme SCHEME=WalletCoreHosted TEST_ACTION=build-for-testing \
  TEST_ONLY=TOSCustodyHostedTests \
  TEST_HOST="$PWD/build/DerivedData/Build/Products/TosWalletDebug-iphonesimulator/TOS Wallet.app/TOS Wallet" \
  TEST_DESTINATION="$TEST_DESTINATION"
```

Use the `.xctestrun` file generated by that build in
`build/DerivedData/Build/Products/`. Keep the corrected output in the same
directory, using a fresh output name:

```sh
python3 scripts/fix_hosted_xctestrun.py "$generated_runfile" "$corrected_runfile"
make test_project_scheme SCHEME=WalletCoreHosted TEST_RUN_FILE="$corrected_runfile" \
  TEST_ONLY=TOSCustodyHostedTests TEST_DESTINATION="$TEST_DESTINATION"
```

Xcode embeds package test bundles in the host's `PlugIns` directory but can
generate a `TestBundlePath` pointing outside it. The helper validates that each
embedded bundle exists, then uses the documented `__TESTHOST__` placeholder.
It preserves other test settings and refuses overwriting a previous run file.
The second command executes already built tests; it does not rebuild or refresh
the application. Rebuild after changing source and retain the exact source and
test-result identity when publishing evidence.

The ordinary `WalletCore` scheme remains available for unhosted unit tests.
The hosted target's missing-role-record checks require the exact
`errSecItemNotFound` result for both PRIMARY and rescue. They do not establish
successful protected-record access, user-presence behavior on physical devices,
deployed account authority, signing, fee solvency or payment delivery. Those
remain separate acceptance requirements.
